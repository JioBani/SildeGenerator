# Astra 감독·배우 자산 전이 계획

목표: 분석·재현에서 얻은 판단이 **새 대본의 첫 제작 품질**로 이어지는지 증명한다. D 장면의 개선을 범용 연기 승인으로 확대하지 않는다.

## 기준선과 경계

- [x] D/C 영상과 D의 부분 승인 기록을 보존한다. 승인 범위는 C 대비 자연스러움과 목·의상 접합뿐이다.
- [x] 사이트의 기존 `astra-motion@0.4.0`을 비교 기준으로 확인했다. `0.7.0`은 2026-09-25에 본 서비스 실행기로 승격했다. 영상 품질의 A/B 비교는 아직 남아 있다.
- [ ] 동일 대본·음성·길이·화풍을 고정한 기준 영상을 등록하고 각각의 파일 해시를 보존한다.
- [ ] 기술, 디자인, 연기, 정보 이해, 감정 몰입, 수정 횟수, 시간, 유료 호출 수를 별도 축으로 기록하는 평가표를 만든다.
- [ ] 이전 최고본을 보존하는 `best_so_far` 결정 및 회귀 시 복귀 절차를 검증한다.

## 1. 재현 경험의 실행 지식화

- [ ] 학습 장부의 각 사례에 관찰, 해석, 수정, 결과, 적용 조건, 반례, 필요한 자산·동작을 구분한다.
- [ ] 원본 디자인의 고유 표현과 새 소재로 전이 가능한 연출 원리를 분리한다.
- [ ] 원본 구간·비교 프레임·사람 판정의 해시를 묶고 변경 시 재검토 상태로 되돌린다.
- [ ] 전이 전 사례는 규칙 후보로 유지한다. 제작용 승인 목록에 자동 등록하지 않는다.

## 2. 대본·디자인·모션 공동 설계

- [x] 선택된 모션 Harness가 지원 문법과 자산 경로를 감독 설계 전에 제시하는 계획 계약을 구현했다 (`0.7.0` 소스).
- [ ] 대본에서 사건, 인과, 사실 주장, 주체 목표, 감정과 공간 관계를 분리한다.
- [ ] 장면 기능과 관객의 이해·감정 변화를 결정하고, 적합한 연출 후보 2~3개와 위험·비용을 비교한다.
- [ ] 장면 기능별 레퍼런스의 출처·권리·관찰과 복제 금지를 기록한다.
- [ ] 디자인안 2~3개를 전달력, 이야기 적합성, 자산화 가능성, 비용으로 비교한다.
- [ ] 색·선·질감·인물 비례·정보 위계·움직임·전환을 디자인 계약으로 확정한다.

## 3. 움직이는 디자인과 배우 자산

- [x] D의 영상, 사람 판정, 프로그램, 몸·머리·표정·목 보정 레이어를 해시로 묶은 연구용 배우 후보를 등록한다.
- [x] D 원본 프로그램의 몸통·머리 좌표, 머리 피벗, 옷깃 가림과 282프레임 회전 범위를 브라우저에서 대조했다. 기술 통과이며 사람 품질 검수는 별개다.
- [ ] 다른 자세에서 같은 조립 관계와 배우 정체성이 유지되는지 검수한다. 원본 장면의 기술 통과를 다른 자세로 확대하지 않는다.
- [ ] 장면마다 통 이미지, 부분 분리, 처음부터 분리 제작, 편집 가능한 그래픽 중 실제 움직임에 맞는 경로를 선택한다.
- [ ] D 배우의 정체성·화풍·캔버스·몸통·머리·얼굴 상태·목 가림 순서를 버전 관리되는 Actor Rig로 저작한다.
- [ ] 팔·전완·손을 필요한 동작에 한해 분리 저작하고 어깨·팔꿈치·손목 피벗과 허용 자세를 등록한다.
- [x] 팔 뻗기 통 자세와 분리 전완·손의 내장 이미지 생성 시안을 만들고 알파·잘림 검사를 수행했다. 둘 다 연구 후보이며 제작 투입은 차단했다.
- [ ] 커튼의 별도 레이어, 손잡이 접촉점, 당김 경로, 가려진 부분과 앞뒤 순서를 저작한다.
- [ ] `주시`, `표정 변화`, `손 뻗기`, `잡기`, `당기기`의 기술 검수와 사람 승인을 각각 분리한다.
- [ ] 중립 조립, 전 동작 경로, 가장자리·그림자·의상 접합, 손·소품 접촉을 검사한다.
- [ ] 배우 ID·리그 버전·자산 해시·능력·허용 구도·승인 범위를 검색 가능한 제작용 장부에 등록한다.
- [ ] 다른 구도와 대본에서 같은 배우의 정체성·동작을 재사용하고 첫 제작 품질을 평가한다.

## 4. 감독 판단에서 출력 프레임까지

- [x] `astra-motion` 계획 계약과 이미지·음성 생성 전 사전 검사를 소스에 연결했다. 실제 자산 존재 검사는 아직 별도 작업이다.
- [ ] 장면별 대상, 의미 상태, 행동 순서, 좌표, 피벗, 접촉·가림 제약을 실행 계약으로 묶는다.
- [ ] 장면의 배우·동작 요구를 제작용 장부의 실제 보유 능력과 대조하고 부족하면 자산 생성 전에 차단한다.
- [ ] 기술·디자인 준비 보고를 실행 계약에 연결하되 보고 자체를 승인으로 취급하지 않는다.
- [ ] 일반 `reaction`의 작은 이동·회전을 얼굴·관절 연기로 표시하거나 대체하지 않는다.
- [ ] 연출 원리 → 자산·동작 버전 → 출력 프레임 → 사람 판정의 증거 체인을 남긴다.

## 5. 대표 장면과 새 대본 전이

- [ ] D를 기반으로 `빛 등장 → 주시 → 표정 → 손 뻗기 → 잡기 → 닫기` 3~5초를 제작한다. 기존 음성·시간표를 고정한다.
- [ ] 타이밍·화면 이탈·접합·접촉을 자동 측정하고, 무음 행동 이해·감정·디자인은 사람에게 각각 묻는다.
- [ ] 실패 원인을 감독 판단, 디자인, 자산, 동작으로 분리해 그 부분만 수정하고 최고본을 유지한다.
- [ ] 다른 대본 두 편과 다른 자산에서 같은 연출 원리·행동 계약을 시험한다.
- [ ] 기존/개선 감독 × 기존/새 실행의 네 조건을 같은 대본·음성으로 비교한다.

## 6. 승격과 배포

- [ ] 첫 시도 품질·이해도·접합·접촉·수정 횟수의 승격 기준을 비교 실험 결과로 확정한다.
- [ ] 통과한 **정확한** 규칙·배우 능력·렌더 버전만 사람 승인 해시와 함께 제작용으로 등록한다.
- [ ] 기능 플래그와 Mock E2E로 사이트 입력부터 재생·다운로드까지 검증한다.
- [ ] 기존 버전 작업 재시도용 runner를 보존하며 새 버전을 점진 배포한다.
- [ ] 근거·자산·승인이 바뀌거나 품질이 나빠지면 승격을 무효화하고 이전 버전으로 복귀한다.

## 0.7.0 실행기 승격 기록

실행 범위와 검증 결과는 [승격 기록](astra-motion-promotion-2026-09-25.md)을 참조한다. 계획 계약, 사전 검사, 디자인 자산 경로 기록을 본 서비스에서 선택 가능한 모션 Harness로 제공한다. 배우 동작과 감독 규칙의 사람 승인 범위는 바뀌지 않았다.

## 이번 작업의 완료 범위

기존 완료 범위는 0단계 증거 보존, 3단계 배우 후보 등록, D 원본 조립 기술 검증과 새 자세 시안의 조기 거부다. D는 아직 독립 관절 리그가 아니고, 손·커튼 동작도 없다. 후보 등록과 원본 프로그램 검증은 제작 승인이나 새 영상의 품질 향상을 의미하지 않는다. 이전 내장 이미지 생성 4회는 연구 시안에 사용했다.

## 추가: 배우 기술 연구 우선 (2026-09-25)

최신 요청에 따라 새 영상 실험보다 오픈소스 구조 분석과 정적 검사를 먼저 진행한다. [연구 비교표](actor_asset_research_matrix.md)를 정본으로 사용한다.

- [x] D/C 증거가 없다는 첨부 문서의 구 작업 폴더 기준 진단을 바로잡았다.
- [x] Inochi2D의 계층·마스크·제어값, OpenToonz의 관절/변형 분리, Iki의 형식·검증기·자동 리거 일부를 commit 고정하여 분석했다.

- [x] 격리된 `ActorRig research-0.1` 규격과 JSON Schema를 만들었다. 서비스 제작 경로에는 연결하지 않았다.
- [x] 부위 계층/가림/관절 범위/행동 선행조건/접촉 좌표 전 프레임 검사, JSON 왕복·해시, 잘못된 승인 입력을 synthetic test로 검증했다.
