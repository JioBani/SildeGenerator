# 이미지에서 실행 가능한 배우로: 자동 분석·동작 선택 공정

후속: [자동 배우화 상세 구현 계획](auto-rig-system-implementation-plan.md). 아래 표는 최초 분석기 구현 시점이며, 현재 관절 드래그/숫자 교정·기록 왕복·Python 재검사까지 추가됐다. 마스크 편집·리깅·동작 실행은 아직 연결되지 않았다.

## 제품 목표와 경계

사용자는 캐릭터 이미지와 의도한 행동을 입력한다. Astra가 대상·부위를 선택하고 자동 분석, 자산 준비, 리깅, 시험 동작, 검수를 실행한다. 한 번의 요청으로 여러 단계를 조율한다는 뜻이지 임의의 사진에서 자연스러운 연기를 무조건 성공시킨다는 보장은 아니다.

기존 서비스와 승인된 D는 보존한다. 모든 신규 실행은 `experiments/image-motion-intake`에 격리한다. 기본 제작·감독 프롬프트·계정 인증·결제 경로는 변경하지 않았다.

## 이번에 실제 구현한 범위

- [로컬 분석기](../experiments/image-motion-intake/motion_intake.py): MediaPipe Pose를 CPU로 실행해 원본 해시·모델 해시·프로그램 해시·33개 원시 관측값을 기록한다. 팔/다리 체인은 그중 해당 관절을 명시적으로 매핑한다.
- 화면 밖 추정, 낮은 visibility/presence, 겹친 관절, 극단적인 투영 길이 비율을 검수 대상으로 표시한다. 투영 길이를 실제 인체 길이로 해석하지 않는다.
- `reach + left/right_arm`, `react + face`, 물체 `translate/rotate`를 서로 다른 준비 경로로 보낸다. 요청에는 이유·대상·목표 위치·시간을 요구한다. 예시 요청은 사람이 작성한 fixture이지 감독 모델이 실제로 선택한 결과가 아니다.
- 모든 실행 권한은 false다. 관절이 관측돼도 레이어·가려진 영역·리그 바인딩·실행 어댑터가 없는 상태를 통과시키지 않는다. 미지원 동작은 줌으로 대체하지 않는다.
- 원화 위 관절 표시 HTML과 JSON 보고서, 12개 단위 테스트, 데스크톱/모바일 브라우저 검사를 추가했다.

## 실측에서 발견한 문제

F 조립본에서 한 인물과 팔 관절이 관측됐다. 반대쪽 전완은 약 22px로 추정되어 상완 약 176px에 비해 지나치게 짧았다. 모델 점수만 통과시키면 잘못된 관절로 리깅할 위험이 있어 길이 비율 0.3~3 밖을 검수 대상으로 추가했다. 이 수치는 임시 보수적 경고값이며 스타일/원근법을 교정하는 인체 규칙이 아니다.

D의 기존 rest 장면에서는 Pose가 인물을 찾지 못했다. 미검출은 기록했으며 임의 좌표를 채우지 않았다. 이는 MediaPipe를 단독 범용 해법으로 채택하면 안 된다는 실제 증거다. 이 두 장면은 독립 정확도 벤치마크가 아니며 자동 리깅 성공률로 계산하지 않는다. 실제 추론은 네트워크 차단 Docker에서 수행했다.

## 단계별 구현 순서

| 단계 | 작업 | 완료 기준 | 현재 |
|---|---|---|---|
| 1 관측 | 사진/그림 입력, 관절 초안, 불확실성·출처 | 좌표/크기/원본 대응, 미검출 처리 | Pose 후보 실행 완료, 물체·얼굴 세부분석 미구현 |
| 2 교정 | 관절 드래그, 부위 마스크 수정, 좌우/가림 확인 | 수정값을 원본 해시에 묶고 원시 추정 보존 | 미구현 |
| 3 자산 | 필요한 부위만 분리, hidden region 보완 | 정지 재조립·윤곽·그림자·접합 검수 | 기존 저작 실험만 있음, 자동 연결 없음 |
| 4 리그 | 표준 골격·피벗·변형 가중치·앞뒤 관계 | 관절 극값과 정해진 시험 동작 재현 | 외부 런타임 어댑터 미구현 |
| 5 선택 | 감독 의도를 지원 능력·대상으로 매핑 | 대상 오선택/도달 불가/미지원 명령 처리 | 명시 요청의 준비 검사만 구현 |
| 6 실행 | 상태별 동작, 시선/표정 타이밍, 접촉 제약 | 고정 FPS와 seek 재현, 픽셀 결함 검수 | 미구현 |
| 7 학습 | 승인 범위·실패·수정량 기록, 다른 배우 시험 | 전이와 첫 시도 품질 개선 증거 | 자동 승격 없음 |

## 감독과 실행기의 역할

감독은 사건의 의미, 어느 대상에 무슨 변화가 필요한지, 시작 신호와 시간, 관객에게 전달할 이유를 결정한다. 부위 분석기는 관측 후보와 불확실성을 제공한다. 실행기는 실제 보유한 자산·동작만 지원한다고 답한다. 물체가 사람처럼 생겼다고 무조건 사람 골격에 넣지 않는다. 회전 소품, 흐르는 액체, 얼굴 연기, 팔 접촉은 별도 동작 계열이다.

첫 지원 범위는 단일 상반신, 작은 반응, 한쪽 팔의 제한된 뻗기다. 걷기·큰 회전·물체 잡기·천 변형·비인간형 캐릭터를 동시 지원한다고 선언하지 않는다. 미검출·가림·범위 밖 행동은 `교정 필요`, `자산 보완 필요`, `동작 미지원`으로 반환한다. 유료 재생성은 사용자 승인 없이 시도하지 않는다.

## 오픈소스 채택 판단

- [MediaPipe Pose](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python): 이번 실제 실행 후보. [모델 카드](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20BlazePose%20GHUM%203D.pdf)는 사진 기반 전신 입력과 가림/방향 등의 한계를 설명하고 Apache-2.0을 명시한다. 만화 이미지의 신뢰도 보장은 없다.
- [Animated Drawings](https://github.com/facebookresearch/AnimatedDrawings): 탐지→분리→관절→모션 적용의 후속 비교 후보. 공식 README상 코드/모델 가중치 MIT, 2025-09-03 보관 상태. 이번 설치·실행·원화/모션 데이터 반입은 하지 않았다.
- [Rive](https://rive.app/docs/editor/manipulating-shapes/bones): 추정된 관절의 저작/실행 후보. 자동 인식기로 취급하지 않는다. 디자인 교체와 결정적 프레임 출력을 검증한 후 선택한다.
- [OpenToonz Plastic](https://opentoonz.readthedocs.io/en/latest/create_animations_using_plastic_tool.html): 비트맵 메시 저작 비교 후보. 가려진 부위 생성이나 의미 연기는 별도다.

## 다음 승격 기준

대표 자세가 다른 자체 이미지 최소 3개에서 관절 교정량과 마스크 수정량을 기록한다. 검증된 리그 한 개에 연결해 같은 반응/뻗기를 실행한다. 디자인 1회 변경 후 비율·정체성·접합을 재검수한다. 사람이 자연스러움과 행동 이해를 승인한 범위만 기존 `actor_assets`, `motion_assets`, `director_safety` 승인 경계에 연결한다. 새 검사기를 기존 승인 권한의 우회로로 만들지 않는다.

현재는 **자동 관절 분석과 준비 경로 판정이 실행되는 실험**이다. 한 번에 자연스러운 캐릭터 영상을 만드는 시스템 전체가 완료된 것은 아니다.
