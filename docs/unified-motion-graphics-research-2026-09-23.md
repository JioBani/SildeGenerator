# 통합 모션그래픽 영상 형식 연구

연구 기준일: 2026-09-23
적용 대상: Astra 감독 엔진과 `astra-motion` 제작 경로
상태: 형식 통합 결정 완료, 장면 전략과 확장 모션 문법은 사람 검수 필요

## 1. 결론

사용자에게 제공하던 `지식 설명형`, `교육형`, `캐릭터형`, `만화형`, `다큐형`은 별개의 영상 형식으로 유지할 만큼 제작 구조가 다르지 않았다. 산소 5초 비교 제작에서도 대본, 핵심 객체, 기본 사건 순서와 상당수 움직임이 같았고 차이는 주로 화면 장식, 진행자 유무, 패널 구성, 자료 고지 방식에 머물렀다.

따라서 모션그래픽을 적극 사용하는 사용자 형식은 **`모션그래픽` 하나로 통합**한다. 기존 이름에서 유용했던 차이는 형식 선택지가 아니라 감독이 장면마다 선택하는 내부 전략으로 흡수한다.

```text
사용자 선택
└─ 모션그래픽
   ├─ 인과 설명
   ├─ 순서 안내
   ├─ 인물 반응
   ├─ 상징 압축
   └─ 근거와 맥락
```

화풍은 형식과 분리한다. 귀여운 캐릭터, 평면 편집 일러스트, 판타지 애니메이션, 시네마틱 사실주의는 동일한 장면 문법에 입힐 수 있는 **표면 디자인 계약**이다. 슬라이드 시네마틱은 정지 이미지와 카메라 연출이 중심인 별도 엔진 축으로 유지한다.

## 2. 근거와 한계

이번 정리는 다음 내부 연구를 종합한다.

- TED-Ed와 사용자가 지정한 설명 애니메이션의 구간 분석
- 자세, 혈압, 조류 독감, GPU, 항생제 장면의 재현 실험
- 산소 5초 대본의 다섯 형식 비교 제작
- 객체 경로, 접촉, 전환, 음향 사건, 카메라와 객체 움직임의 분리 측정
- Remotion 및 HyperFrames/GSAP 제작 실험
- 사용자 피드백으로 승인 또는 기각된 섀클턴 장면 사례

이 문서의 `관찰`은 실제 분석·재현 기록에서 반복 확인된 내용이다. `가설`은 다음 비교 실험이 필요한 판단이다. 원본 영상의 그림이나 음성을 제작 자산으로 복제하지 않았으며, 여기서 학습은 모델 가중치 훈련이 아니라 **관찰, 계약, 자산, 테스트, 실패 기록을 엔진에 축적하는 것**을 뜻한다.

## 3. 반복해서 발견된 핵심 문법

### 3.1 장면은 장식이 아니라 관객 상태를 바꾸는 단위다

좋은 장면은 먼저 `이 장면 전후에 관객이 무엇을 다르게 이해해야 하는가`가 정해져 있었다. 화면 요소와 움직임은 그 변화를 돕는다.

```text
대본 단위
→ 관객의 질문
→ 장면 기능
→ 표현 방식
→ 레이아웃
→ 객체와 상태
→ 움직임
→ 전환
→ 읽기 시간
```

장면 기능 없이 화풍이나 효과부터 선택하면 예쁜 요소가 늘어도 정보 전달은 좋아지지 않았다.

### 3.2 움직임은 상태·관계·주의의 변화를 보여줘야 한다

유효한 움직임은 최소한 하나를 수행했다.

- 객체의 상태 변화: 정상 → 손상, 비활성 → 활성
- 공간 관계 변화: 분리 → 결합, 이동 → 도착
- 인과 과정: 압력 증가 → 변형 → 파손
- 주의 이동: 전체 → 핵심 대상, 인물 → 대상
- 수량 구조 변화: 하나 → 다수, 한 집단 → 두 집단
- 시간 진행: 단계 시작 → 수행 → 완료

그 어떤 변화도 설명하지 않는 움직임은 정지 또는 짧은 유지가 더 낫다. 계속 떠다니는 장식, 동일한 줌인, 의미 없는 펄스는 생동감이 아니라 잡음이 되었다.

### 3.3 읽기 순서는 안무 순서가 된다

모든 요소를 동시에 등장시키면 정보 위계가 사라졌다. 성공적인 설명 장면은 대체로 다음 리듬을 갖는다.

```text
기준 상태 제시
→ 핵심 대상 선택
→ 변화 실행
→ 결과 강조
→ 읽기 유지
→ 정착
```

`anticipation → action → impact → reaction → settle`은 사건 장면에, `question → cause → state change → consequence → hold`는 인과 설명에 유효했다. 단, 모든 장면에 같은 박자로 강제하면 템플릿처럼 보이므로 장면 기능에 따라 단계를 생략하거나 늘려야 한다.

### 3.4 동일 객체의 정체성을 전환 너머까지 유지해야 한다

좋은 전환은 새 그림으로 바뀌는 것이 아니라 같은 대상의 의미가 확장되는 과정으로 읽혔다.

- 칩이 작아지며 관련 요소가 들어올 공간을 만든다.
- 태양과 시계가 중심과 원형 실루엣을 공유한다.
- 인물 또는 세포가 확대·축소되어도 색, 표식, 방향이 유지된다.
- 현실 장면의 대상이 도식 장면에서도 대응되는 색과 위치를 가진다.

객체 정체성이 끊기면 관객은 상태 변화가 아니라 새 장면으로 인식한다. 따라서 전환 계약에는 `무엇이 같은 대상인지`, `무엇이 바뀌는지`, `어떤 속성은 유지되는지`가 필요하다.

### 3.5 공간 관계와 접촉은 장면 의미의 일부다

자세와 혈압 분석에서 위치, 접촉, 가림 순서는 미술 세부가 아니라 사건 자체였다.

- 골반은 의자에 지지되어야 한다.
- 손과 책상, 눈과 모니터의 목표 관계가 유지되어야 한다.
- 입자가 혈관 벽을 통과하면 안 된다.
- 도구가 목표 경로에서 이탈하거나, 잡은 물체가 손과 따로 움직이면 안 된다.
- 전경과 배경의 가림 순서는 공간 깊이와 접촉을 설명한다.

따라서 객체 좌표만 저장해서는 부족하다. 앵커, 피벗, 접촉 대상, 허용 거리, 가림 순서, 유지 구간을 함께 계약해야 한다.

### 3.6 카메라는 정보 순서를 전달해야 한다

사용자 피드백과 섀클턴 장면에서 줌은 다음처럼 의미가 달랐다.

- 얼굴로 접근: 감정·인지·결정에 집중
- 인물에서 빠져나오기: 개인의 노력에서 환경의 규모로 확장
- 산맥으로 접근: 장애의 험난함을 강조
- 구조선으로 접근: 귀환 사건의 핵심 대상을 명시

카메라는 장면의 주인공과 정보 순서를 바꾼다. 자동 줌은 화면 중앙이 아니라 `focal object`, `viewer takeaway`, `다음 장면과의 관계`에서 목표를 정해야 한다. 객체 움직임과 카메라 움직임도 별도로 기록해야 한다.

### 3.7 추상화는 현실과 연결될 때 설명력이 생긴다

설명 애니메이션은 현실적 맥락과 추상 도식을 왕복했다.

```text
현실의 문제
→ 대상 선택
→ 내부/추상 세계로 전환
→ 과정과 관계 설명
→ 현실의 결과로 복귀
```

GPU 공장 은유처럼 상징을 사용할 때는 대응표가 필요하다. 작업 항목, 처리 장치, 결과가 각각 무엇을 뜻하는지 명시하고, 은유가 실제 구조라고 오해될 범위를 기록해야 한다.

### 3.8 인물의 생동감은 지속 운동보다 반응 사건에서 나온다

인물을 항상 흔들거나 호흡시키는 것보다 `자극 → 시선 획득 → 얼굴 변화 → 고개 → 몸통 → 유지 → 정착`의 한 번의 반응이 더 큰 의미를 만들었다.

```text
EVENT
→ PERCEPTION
→ INTERNAL CHANGE
→ VISIBLE PERFORMANCE
```

눈, 눈썹, 입, 고개, 몸통이 모두 같은 프레임에 출발하면 기계적으로 보인다. 반응은 시간차가 필요하지만, 자연스러움은 자동 수치만으로 승인할 수 없으므로 사람의 연기 검수가 남는다.

### 3.9 음향은 보이는 원인과 맞아야 한다

파손음, 충격음, 등장음은 시각 사건보다 먼저 또는 늦게 들리면 장면의 물리성이 깨졌다. 음향 시간표는 계획된 전체 길이가 아니라 **실제 존재하는 컷과 객체 사건**을 기준으로 다시 계산해야 한다. 존재하지 않는 컷을 참조하거나 장면 경계를 넘는 음향은 렌더 전에 차단한다.

## 4. 통합 형식의 내부 장면 전략

이 전략들은 사용자가 고르는 장르가 아니다. 감독 엔진이 장면의 목적에 따라 하나를 주 전략으로 선택하고 필요하면 보조 전략을 결합한다.

| 전략 | 적용 조건 | 기본 문법 | 주요 위험 |
|---|---|---|---|
| 인과 설명 `causal_explanation` | 왜 한 상태가 다른 결과를 만드는지 설명 | 질문 → 원인 → 상태 변화 → 결과 → 유지 | 상관관계를 인과처럼 표현, 과도한 장식 |
| 순서 안내 `guided_sequence` | 절차, 단계, 관찰 순서가 중요 | 목표 → 현재 단계 → 행동/관찰 → 결과 → 확인 | 모든 대본을 사용법 영상처럼 평면화 |
| 인물 반응 `character_response` | 감정, 인지, 선택이 의미를 운반 | 자극 → 시선 → 반응 → 설명 → 정착 | 반응 남용, 리그 없는 가짜 몸짓 |
| 상징 압축 `symbolic_compression` | 사건을 짧고 강하게 요약 | 설정 → 예고 → 충격 → 반응 → 결과 | 과장으로 사실 왜곡, 만화 효과의 목적 상실 |
| 근거와 맥락 `evidence_context` | 주장·자료·재현을 구분해야 함 | 주장 → 근거 → 출처 상태 → 맥락 → 해석 | 삽화를 실제 자료처럼 보이게 함 |

한 장면은 `인물 반응 + 인과 설명`처럼 결합할 수 있다. 그러나 주 전략 하나를 지정해 정보 우선순위를 잃지 않게 한다.

## 5. 표현 방식은 전략과 별개다

같은 인과 설명도 여러 방식으로 표현할 수 있다.

- 공간 장면: 인물, 장소, 배, 산맥처럼 실제 위치 관계가 중요
- 도식: 원인과 결과, 비교, 수량 구조를 단순화
- 단면·과정: 보이지 않는 내부 변화와 흐름을 노출
- 지도·경로: 출발, 이동, 도착, 거리와 방향을 설명
- 인물 연기: 시선, 표정, 자세, 접촉을 통해 의미 전달
- 증거·문서: 사진, 기록, 수치의 출처 상태를 명시
- 상징·은유: 추상 개념을 대응 관계로 압축

형식 통합은 이 차이를 없애는 것이 아니다. **고정된 장르 프레임 대신 장면마다 가장 적합한 표현 방식을 선택하는 것**이다.

## 6. 발견된 재사용 가능 모션 문법

| 문법 | 전달하는 의미 | 필요한 계약 |
|---|---|---|
| 목적 있는 등장 | 새 정보의 도입 | 등장 순서, 읽기 유지 |
| 경로 이동 | 출발·진행·도착 | 실제 경로, 방향, 속도, 도착 상태 |
| 집단 분리·병합 | 분류, 선택, 재결합 | 구성원 정체성, 수량 보존 |
| 상태 변화 | 손상, 성장, 활성화 | 전·후 상태, 바뀌는 속성, 불변 속성 |
| 반응 연쇄 | 사건이 인물에게 미친 영향 | 자극 대상, 시선, 얼굴, 고개, 몸통 |
| 접촉과 유지 | 가리키기, 잡기, 지지 | 앵커, 피벗, 접촉 오차, 유지 시간 |
| 흐름·축적·압력 | 보이지 않는 과정 | 경계, 입자 경로, 밀도, 변형 관계 |
| 초점 이동 | 정보 순서와 의미 확대 | 시작·종료 초점, 카메라/객체 분리 |
| 매치 전환 | 같은 개념의 표현 전환 | 중심, 실루엣, 색, 정체성 보존 |
| 유지와 정착 | 관객의 이해 시간 | 최소 읽기 시간, 다음 사건 전 안정 구간 |

현재 `astra-motion`의 일반 컴파일러가 직접 실행하는 효과는 `camera_push`, `reveal`, `emphasize`, `progress` 중심이다. 스키마에는 더 많은 문법이 선언돼 있지만, 선언이 곧 구현 능력을 의미하지 않는다. 위 표의 다수는 연구 예제에서 개별 구현됐을 뿐 일반 자동 제작 능력으로 승격되지 않았다.

## 7. 통합 제작 계약

```text
SCRIPT UNIT
→ VIEWER QUESTION
→ SCENE FUNCTION
→ PRIMARY STRATEGY
→ REPRESENTATION MODE
→ DESIGN CONTRACT
→ LAYOUT AND FOCAL ORDER
→ OBJECTS, STATES, ANCHORS
→ MOTION CHOREOGRAPHY
→ TRANSITION AND IDENTITY
→ RHYTHM AND AUDIO EVENTS
→ TECHNICAL REVIEW
→ HUMAN MEANING / DESIGN / ACTING REVIEW
→ GOLD COMPARISON
→ EXPERIENCE EXTRACTION
```

장면 계약의 최소 필드는 다음과 같다.

```yaml
scene_function: explain_cause
viewer_takeaway: "산소가 구조를 지탱한다"
primary_strategy: causal_explanation
representation_mode: cross_section
layout:
  focal_order: [structure, oxygen_bonds, collapse]
objects:
  - id: structure
    state_before: stable
    state_after: collapsed
    identity_locked: true
motion:
  - target: oxygen_bonds
    semantic_reason: remove_support
    phases: [anticipation, disappear, consequence, settle]
transition:
  identity_preserved: [structure]
rhythm:
  minimum_read_hold_seconds: 1.2
source_status: hypothetical_reconstruction
```

## 8. 품질 게이트

1. **대본·사실 검수**: 주장, 가정, 출처와 과장을 구분한다.
2. **감독 설계 검수**: 관객 질문, 장면 기능, 표현 방식, 정보 순서를 확인한다.
3. **디자인 계약 검수**: 색, 선, 질감, 형태, 객체 정체성과 편집 가능성을 확인한다.
4. **자산 준비도 검수**: `STATIC_READY`, `MOTION_READY`, `REACTION_READY`, `INTERACTION_READY`를 구분한다.
5. **스타일 프레임 검수**: 화풍 기준과 실제 제작 자산을 혼동하지 않는다.
6. **대표 장면 검수**: 가장 위험한 인과, 반응, 접촉, 전환을 먼저 제작한다.
7. **전체 렌더 기술 검수**: 프레임 탐색, 누락, 겹침, 음향 경계, 길이, 해시를 확인한다.
8. **사람 품질 검수**: 의미, 디자인, 연기, 자연스러움, 오해 가능성을 확인한다.
9. **Gold 회귀 검수**: 새 결과를 최고 승인본과 비교하고 나빠지면 이전 버전을 유지한다.
10. **경험 추출**: `이전 결과 → 문제 → 원인 → 변경 변수 → 결과 → 적용 조건 → 반례`를 저장한다.

## 9. 금지 규칙

- 장르 이름만으로 고정 레이아웃을 선택하지 않는다.
- 화면에 없는 객체에 움직임을 등록하지 않는다.
- 모든 객체를 동시에 같은 이징으로 시작하지 않는다.
- 의미 변화가 없는 장식 모션을 기본값으로 넣지 않는다.
- 중앙 좌표를 자동 카메라 목표로 간주하지 않는다.
- 한 장의 합성 이미지를 잘라 객체처럼 움직여 공간을 깨뜨리지 않는다.
- 정지 자산을 관절·표정·접촉 가능한 자산으로 오인하지 않는다.
- 기술 렌더 성공을 디자인·연기 승인으로 간주하지 않는다.
- 재현 삽화를 실제 기록 자료처럼 표시하지 않는다.
- 단일 성공 사례를 보편 규칙으로 자동 승격하지 않는다.

## 10. 현재 구조의 핵심 부족분

### 구현 부족

- 일반 컴파일러의 모션 어휘가 기본 등장과 카메라 효과에 치우쳐 있다.
- 객체별 레이어, 앵커, 피벗, 접촉 제약이 모든 제작 경로에 연결되지 않았다.
- 인물 표정·시선·고개·몸통 리그와 접촉 연기는 사람 승인 전 연구 단계다.
- 지도, 단면, 입자 흐름, 집단 변화는 개별 연구 예제가 있으나 범용 저작기로 통합되지 않았다.

### 판단 부족

- 장면 전략을 선택하는 명시적 점수와 근거 기록이 아직 약하다.
- 관객 이해도를 자동 측정할 수 없고 사람 검수가 필요하다.
- 이론, 레퍼런스 관찰, 감독 경험, 프로젝트 취향의 신뢰도 계층이 제작 시 완전히 소비되지 않는다.
- 전체 레퍼런스 분석은 진행 중이며 일부 구간 성공을 완전 재현으로 볼 수 없다.

### 운영 부족

- 실패 수정이 다음 제작의 강제 계약으로 연결되는 비율을 계측해야 한다.
- 새 버전이 Gold보다 나빠졌을 때 자동으로 이전 최고본을 유지하는 경로를 더 넓혀야 한다.
- 장면별 작업 시간, 수정 횟수, 호출 수, 기각 원인을 같은 장부에 모아야 한다.

## 11. 개편 우선순위

### P0. 단일 형식 정착

- 사용자 장르 선택 제거
- `모션그래픽`과 `슬라이드 시네마틱`만 엔진 축으로 노출
- 기존 장르 데이터는 과거 기록 호환용으로만 읽기
- 화풍 선택은 독립 유지

### P1. 장면 전략을 실행 계약으로 만들기

- 모든 장면에 주 전략, 관객 변화, 표현 방식 기록
- 전략별 필수 객체 상태와 금지 조건 검사
- 설명 없는 움직임과 대상 없는 움직임을 렌더 전에 차단

### P2. 객체 단위 저작과 모션 어휘 확장

- 경로 이동, 집단 변화, 상태 변화, 매치 전환을 일반 컴파일러에 추가
- 객체별 레이어, 앵커, 피벗, 가림, 접촉 계약 추가
- 카메라와 객체 궤적을 독립 저장

### P3. Gold Bench

- 인과 설명, 집단 분리, 지도 이동, 인물 반응, 접촉 유지, 단면 흐름의 대표 장면 구축
- 정지판과 새 후보를 Blind A/B로 비교
- 기술, 의미, 디자인, 연기 점수를 분리

### P4. 학습 루프

- 승인된 수정만 감독 경험으로 승격
- 세 번 반복되는 실패는 개별 장면 수정이 아니라 원인 계약을 개편
- 다른 대본으로 전이 검증 후 적용 범위를 확대

## 12. 성공 지표

- 첫 설계에서 사람에게 승인되는 장면 비율
- 에피소드당 사람 수정 횟수와 같은 실패의 재발률
- 화면 객체와 모션 대상의 일치율
- 접촉·경로·수량·정체성 위반 수
- 장면별 핵심 의미를 무음으로 이해한 검수자 비율
- 근거와 재현 상태의 올바른 표시율
- Gold 대비 퇴행 장면 수
- 분당 제작 시간, 렌더 재시도, 유료 호출 수

속도와 비용은 품질과 재현성이 안정된 뒤 최적화한다. 초기 목표는 `빠른 제작`이 아니라 **같은 감독 판단이 다른 대본에서도 반복되는가**다.

## 14. 최종 운영 원칙

모션그래픽의 형식 차이는 이름표에서 나오지 않는다. 같은 영상 안에서 장면마다 `무엇을 이해시킬지`, `어떤 대상으로 보여줄지`, `어떤 상태를 어떻게 바꿀지`, `얼마나 기다려 읽게 할지`를 다르게 설계하는 데서 나온다.

따라서 Astra의 모션그래픽 엔진은 하나이며, 그 안에서 감독이 장면별 문법과 디자인·자산·움직임을 선택한다. 엔진의 발전은 효과 수를 늘리는 것이 아니라 **의미 있는 장면 결정을 실행 가능한 객체 계약으로 바꾸고, 결과를 검수해 다음 제작에 재사용하는 능력**으로 측정한다.
