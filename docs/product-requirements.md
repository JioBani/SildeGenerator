# Slide Generator 제품 요구사항 및 완성 정의

> 이 문서는 사용자 요구사항을 지속해서 정리하는 기준 문서다. 확정된 요구사항과 아직 결정되지 않은 사항을 구분하여 관리한다.

## 0. 문서 관리 기준

- 사용자가 명시적으로 결정한 내용은 본문의 요구사항으로 기록한다.
- 아직 선택하지 않았거나 운영·검증 기준이 필요한 내용은 `미확정 사항`에 둔다.
- 사용자의 최신 결정이 이전 내용과 충돌하면 최신 결정을 우선한다.
- 첫 출시의 필수 범위와 후순위 범위를 구분한다. 후순위 기능은 첫 출시의 완성 조건에 포함하지 않는다.
- 여기서 말하는 영상 품질은 전문 편집자가 만드는 수준의 세밀함보다, 대본의 의미가 전달되고 이미지·나레이션·자막이 어색하지 않게 연결되는 수준을 우선한다.

### 현재 범위 요약

| 구분 | 내용 |
| --- | --- |
| 첫 출시 필수 | 비로그인 생성 전 체험, 카카오·네이버·구글 로그인, 대본 입력, 비정형 대본 자동 해석, 슬라이드형 영상, 대표 이미지가 있는 스타일 선택, ElevenLabs 목소리 선택·미리듣기, 나레이션 속도, 자막 포함 여부, 16:9·9:16 화면 비율, 배경음악, 예상 길이·사용량 안내, 단계·진행률이 있는 생성 화면, 자동 품질검사·복구, 다중 작업 큐·상태 관리, 계정별 작업 목록, 서비스 내부 완료 알림, 결과 재생·다운로드·동일 설정 다시 만들기 |
| 후순위 | 모션그래픽 영상 및 그 하위 스타일, 해당 효과에 맞는 영상 형식·스타일이 개발된 이후의 현재 읽는 단어·문장 색상 강조 |
| 현재 제공하지 않음 | 생성 전 정리된 나레이션 확인, 생성 중 일시정지·취소, 생성 중 또는 생성 후 부분 편집, 자동 인트로·아웃트로, 서비스 로고·워터마크, 이메일·문자·메신저를 통한 외부 완료 알림 |

## 1. 제품 목표

사용자가 대본과 원하는 영상 스타일을 선택하면, 선택한 스타일의 시각적·연출적 특성이 일관되게 반영된 영상을 생성한다.

영상 제작 방법을 모르거나 기존 영상 편집기와 AI 영상 생성 서비스를 사용하기 어려운 사람도 대본과 몇 가지 설정만으로 자신의 이야기가 담긴 영상을 만들 수 있게 한다. 세부적인 영상 품질을 극대화하는 것보다 누구나 저렴한 비용으로 쉽게 영상을 완성할 수 있게 하는 것을 우선한다.

## 1.1 핵심 사용자

- 첫 출시 버전의 핵심 사용자는 간단하게 영상을 만들고 싶은 40~50대다.
- 영상 편집 경험이 없거나 매우 적다.
- 시중의 영상 편집 프로그램이나 AI 영상 생성 서비스를 사용하는 방법을 모른다.
- 직접 편집 기술을 배우기보다 자신의 대본과 이야기를 영상으로 빠르게 만들고 싶어 한다.
- 전문 제작자 수준의 세부적인 영상 품질보다 쉬운 사용법과 저렴한 비용을 중요하게 생각한다.

## 1.2 제품 설계 원칙

1. 사용자는 영상 편집 지식 없이도 영상을 만들 수 있어야 한다.
2. 기본 과정은 `대본 입력 → 몇 가지 설정 선택 → 영상 만들기 → 결과 확인`으로 유지한다.
3. 편집 기능과 복잡한 세부 설정은 제공하지 않는다.
4. 사용자가 이해하기 어려운 영상 제작 전문 용어와 기술 설정은 노출하지 않는다.
5. 선택 항목은 결과에 의미 있는 차이를 만드는 최소한의 설정으로 제한한다.
6. 전문가 수준의 미세 조정보다 첫 사용자의 이해 가능성과 작업 완료 가능성을 우선한다.
7. 세부 품질을 높이기 위해 사용법이나 비용이 크게 복잡해지는 기능은 우선순위를 낮춘다.
8. 원래 영상을 만들 수 없었던 사용자가 부담할 수 있는 가격으로 영상을 완성하게 하는 것을 목표로 한다.

## 1.3 대표 사용 사례

첫 출시 버전에서 기준으로 삼는 대표 사용 사례는 다음과 같다.

1. 사용자는 성경과 관련된 이야기를 다른 사람에게 간단하게 전달하고 싶어 한다.
2. 약 10분 분량의 완성된 대본을 미리 준비한다.
3. 서비스에 접속해 준비한 대본을 복사하여 붙여넣는다.
4. 원하는 이미지 스타일을 선택한다.
5. 영상 생성을 요청하고 별도의 편집 없이 기다린다.
6. 시스템은 대본을 여러 장면으로 나누고 슬라이드 이미지의 연속, 자막과 대본을 읽는 나레이션으로 영상을 구성한다.
7. 사용자는 완성된 영상을 내려받는다.
8. 사용자는 별도의 후편집 없이 완성 영상을 그대로 YouTube에 게시한다.

이 사용 사례는 종교 콘텐츠로 서비스 범위를 제한한다는 의미가 아니라, 핵심 사용자의 전체 경험과 제품 완성도를 판단하기 위한 대표 기준이다.

## 2. 핵심 사용자 흐름

1. 사용자가 영상 대본을 입력하고, 원하는 경우 같은 화면에서 자신의 배경음악 파일을 함께 업로드한다.
2. 시스템은 형식이 일정하지 않은 입력에서도 실제 나레이션과 구조·메모·연출 지시를 자동으로 구분한다.
3. 시스템이 실제로 읽을 나레이션을 기준으로 예상 영상 길이를 계산해 표시한다.
4. 대본 입력 영역 아래에 선택 가능한 영상 스타일을 표시한다.
5. 사용자가 원하는 스타일을 선택한다.
6. 사용자가 각 목소리의 짧은 미리듣기를 듣고 ElevenLabs 나레이션 목소리를 선택한다.
7. 사용자가 나레이션 속도를 조절한다.
8. 사용자가 `16:9` 또는 `9:16` 영상 비율을 선택한다.
9. 사용자가 기본으로 켜져 있는 자막을 그대로 사용하거나 끈다.
10. 사용자가 직접 배경음악을 제공하지 않았다면 시스템의 자동 선곡을 사용한다.
11. 비로그인 사용자도 이 단계까지 대본을 입력하고 예상 영상 길이를 확인하는 등 생성 전 과정을 체험할 수 있다.
12. 사용자가 영상 생성을 요청할 때 로그인하지 않은 상태라면 카카오, 네이버 또는 구글 계정으로 로그인한다.
13. 예상 영상 길이가 최대 30분 이내이고 예상 사용량 이상의 잔액이 있으면 사용자가 영상 생성을 시작할 수 있다.
14. 화면은 영상 제작 현황을 중심으로 보여주는 큰 진행 화면으로 전환된다.
15. 시스템은 입력한 대본을 바탕으로 선택한 스타일, 목소리, 나레이션 속도, 영상 비율, 자막과 배경음악 설정에 맞는 영상을 생성한다.
16. 사용자는 제작 중인 영상의 현재 작업 단계와 전체 진행률을 확인한다.
17. 사용자가 생성 화면을 닫거나 다른 페이지로 이동해도 서버에서 영상 제작을 계속한다.
18. 시스템은 결과 공개 전에 생성 이미지와 완성 영상의 이상 여부를 자동 검사하고, 발견한 문제의 재생성 또는 복구를 시도한다.
19. 복구와 최종 검사를 통과한 영상만 완료 처리한다.
20. 영상 제작이 완료되면 실제 완성 영상 길이를 기준으로, 현재 잔액을 넘지 않는 범위에서 사용량이 차감된다.
21. 서비스 내부에 작업 완료 알림을 표시한다.
22. 완료 화면에서 사용자는 영상을 재생하거나 내려받고, `다시 만들기`로 같은 대본과 설정의 새 영상 생성을 즉시 요청할 수 있다.
23. 새 영상이 생성되어도 이전 영상은 작업 목록에 그대로 보관된다.
24. 기존 영상이 생성 중이어도 사용자는 다른 영상 생성을 추가로 요청할 수 있다.
25. 사용자는 나중에 다시 로그인해 작업 목록의 진행 상태를 확인하고, 보관 중인 영상을 재생하거나 다시 내려받을 수 있다.

## 3. 스타일 분류 체계

아래 분류와 명칭은 현재 설계를 위한 **잠정안**이다. 개발과 품질 검증 결과에 따라 엔진의 경계, 이름과 하위 스타일 구성이 변경될 가능성이 높다.

### 3.1 슬라이드형 시네마틱 엔진(잠정 명칭)

- 이미지 또는 장면 단위의 슬라이드를 중심으로 화면 전환, 자막과 나레이션을 조합한다.
- 현재 하위 스타일은 `귀여운 캐릭터 주도형`과 `일본 판타지 애니메이션풍`이다.
- 이후 다큐멘터리풍, 회화풍, 실사풍 등의 하위 스타일로 확장할 수 있다.
- 문서의 기존 `슬라이드 쇼 영상` 요구사항은 현재 잠정 구조에서 이 엔진을 가리킨다.

### 3.2 모션그래픽 엔진(잠정 명칭)

- 객체, 도식과 타이포그래피를 중심으로 움직임을 구성한다.
- 대본의 내용과 흐름에 맞는 시각적 움직임을 제공한다.
- 구체적인 하위 스타일은 아직 정하지 않았다.

### 3.3 확장 원칙

- 현재 구조에서 새로운 스타일은 `슬라이드형 시네마틱 엔진` 또는 `모션그래픽 엔진` 중 하나를 상위 엔진으로 사용한다.
- 상위 형식의 공통 제작 방식을 재사용하면서 색상, 화풍, 장면 구성, 움직임, 전환 등의 테마를 달리해 스타일을 확장한다.
- 스타일 종류를 추가하더라도 사용자의 기본 흐름은 바뀌지 않아야 한다.
- 상위 엔진이나 하위 스타일의 명칭이 바뀌어도 기존 생성 흐름과 저장된 작업이 깨지지 않아야 한다.

### 3.4 출시 우선순위

#### 1순위: 슬라이드형 시네마틱 엔진

- 첫 출시에서 반드시 완성도 있게 제공해야 하는 핵심 영상 형식이다.
- 대표 사용 사례인 약 10분 분량의 YouTube 영상을 안정적으로 만들 수 있어야 한다.
- 이미지, 자막과 나레이션의 내용 및 타이밍이 자연스럽게 연결되어야 한다.
- 슬라이드형 영상의 완성 조건을 충족하지 못하면 제품을 완성된 것으로 보지 않는다.

#### 후순위: 모션그래픽 영상

- 제공되면 제품의 가치를 높일 수 있지만 첫 출시의 필수 범위는 아니다.
- 슬라이드형 영상의 품질과 안정성을 확보한 뒤 개발한다.
- 모션그래픽 기능이 준비되지 않았다는 이유만으로 첫 출시를 지연하지 않는다.
- 미완성 상태의 모션그래픽 기능을 핵심 사용자에게 공개하지 않는다.

## 4. 기능 요구사항

### FR-001 대본 입력

- 사용자는 영상 제작에 사용할 대본을 입력할 수 있어야 한다.
- 약 10분 분량의 영상이 될 수 있는 대본을 한 번에 붙여넣고 처리할 수 있어야 한다.
- 기본 입력은 처음부터 끝까지 읽는 나레이션 대본을 기준으로 한다.
- 사용자가 항상 정해진 대본 형식을 지킨다고 가정해서는 안 된다.
- 최대 길이 안의 긴 대본도 여러 편으로 자동 분할하지 않고 하나의 완성 영상 파일로 생성해야 한다.

### FR-002 스타일 목록 표시

- 대본 입력 영역 아래에 선택 가능한 스타일을 표시해야 한다.
- 모든 스타일 선택 항목에는 해당 스타일을 시각적으로 보여주는 대표 이미지가 반드시 있어야 한다.
- 각 스타일이 슬라이드형 시네마틱과 모션그래픽 중 어느 엔진에 속하는지 사용자가 이해할 수 있어야 한다.

### FR-003 스타일 선택

- 사용자는 영상 생성 전에 하나의 스타일을 선택할 수 있어야 한다.
- 영상 생성 요청에는 선택한 스타일 정보가 포함되어야 한다.

### FR-004 스타일 기반 영상 생성

- 시스템은 선택한 스타일에 정의된 화면 구성과 연출 규칙을 사용해 영상을 생성해야 한다.
- 단순히 스타일 이름만 기록하는 것이 아니라 실제 결과 영상에서 해당 스타일의 특징을 확인할 수 있어야 한다.
- 슬라이드형 영상에서는 대본을 장면으로 나누고 각 장면에 맞는 슬라이드 이미지를 순서대로 구성해야 한다.
- 슬라이드 이미지, 자막과 나레이션의 내용 및 타이밍이 서로 자연스럽게 맞아야 한다.
- 최소한 동일한 씬 안에서는 화풍, 인물, 배경과 주요 시각 요소가 갑자기 달라지지 않고 일관되게 유지되어야 한다.

### FR-005 스타일 확장

- 기존 생성 흐름을 변경하지 않고 새로운 하위 스타일을 추가할 수 있어야 한다.
- 스타일별 설정과 제작 규칙이 다른 스타일에 불필요한 영향을 주지 않아야 한다.

### FR-006 영상 제작 진행 화면

- 사용자가 `영상 만들기`를 누르면 영상 제작 현황이 중심이 되는 큰 화면을 표시해야 한다.
- 진행 화면에는 전체 작업의 진행률을 표시해야 한다.
- 현재 수행 중인 제작 단계를 사용자가 이해할 수 있는 표현으로 표시해야 한다.
- 작업 단계와 전체 진행률은 진행 화면에서 함께 확인할 수 있어야 한다.
- 제작 상태가 바뀌면 사용자가 화면을 새로고침하지 않아도 진행 정보가 갱신되어야 한다.
- 제작이 완료되면 같은 흐름 안에서 완성 영상을 확인할 수 있어야 한다.

### FR-007 생성 전 예상 영상 길이

- 사용자가 대본을 입력하면 영상 생성 전에 예상 영상 길이를 표시해야 한다.
- 예상 길이는 시스템이 실제로 읽을 나레이션과 사용자가 선택한 나레이션 속도를 기준으로 계산해야 한다.
- 사용자는 영상을 생성하기 전에 예상 사용량을 판단할 수 있어야 한다.
- 최소 영상 길이는 제한하지 않는다.
- 초기 최대 영상 길이는 30분으로 제한한다.
- 예상 영상 길이가 30분을 초과하면 영상 생성을 시작할 수 없어야 한다.
- 최대 30분 제한은 실제 제작 안정성 검증 결과에 따라 다시 조정할 수 있다.

### FR-008 영상 길이 기반 사용량

- 사용량은 영상 길이를 기준으로 관리한다.
- 사용자 화면에는 사용량을 별도 크레딧으로 변환하지 않고 `영상 제작 가능 시간`으로 표시해야 한다.
- 사용자는 30분, 1시간 등 운영자가 미리 정한 시간 상품을 일시불로 구매해 영상 제작 가능 시간을 충전한다.
- 충전 상품은 구독제가 아니며, 정기 결제나 정기 갱신을 전제로 하지 않는다.
- 충전한 영상 제작 가능 시간에는 유효기간을 두지 않는다.
- 사용자의 남은 사용량이 예상 영상 길이보다 적으면 영상 생성을 시작할 수 없어야 한다.
- 사용량이 부족한 경우 필요한 사용량과 부족한 양을 안내하고 충전하도록 안내해야 한다.
- 영상 제작이 정상적으로 완료되면 실제 완성된 영상 길이에 해당하는 사용량을 차감해야 한다.
- 생성 전 잔액 검사는 예상 길이를 기준으로 하지만, 완료 후 차감량은 실제 완성 영상 길이를 기준으로 계산해야 한다.
- 실제 완성 영상이 예상보다 길어도 차감 시점의 현재 잔액까지만 차감하고 잔액을 0에서 멈춰야 한다.
- 어떤 경우에도 사용자의 영상 제작 가능 시간 잔액을 음수로 만들지 않는다.
- 오류로 실패하거나 그 밖의 이유로 사용자가 완성 영상을 받지 못한 작업은 사용량을 차감하지 않는다.
- 현재 보유 사용량, 예상 차감량과 완료 후 실제 차감량을 사용자가 이해할 수 있어야 한다.
- 사용하지 않은 잔액의 환불 가능 여부와 조건은 별도의 환불 정책으로 정의해야 한다.

### FR-009 생성 제어 및 수정 범위

- 영상 생성이 시작된 뒤에는 사용자가 작업을 일시정지하거나 중간에 취소할 수 없다.
- 접수된 작업은 정상적으로 완료되거나 오류로 실패할 때까지 진행된다.
- 영상 제작 도중 또는 제작 완료 후 결과를 부분 수정하는 기능은 제공하지 않는다.
- 결과를 변경하려면 대본이나 스타일을 바꿔 영상을 새로 생성해야 한다.

### FR-010 자막 포함 여부

- 사용자는 영상 생성 전에 자막 포함 여부를 선택할 수 있어야 한다.
- 자막은 기본적으로 포함된 상태(`ON`)여야 한다.
- 자막을 포함하도록 선택하면 완성 영상에 대본과 동기화된 자막이 표시되어야 한다.
- 자막은 긴 문단을 한꺼번에 표시하지 않고 읽기 쉬운 짧은 문장 단위로 나눠야 한다.
- 나눠진 각 자막은 해당 내용을 읽는 나레이션 타이밍에 맞춰 표시되어야 한다.
- 자막을 포함하지 않도록 선택하면 완성 영상에 자막이 표시되지 않아야 한다.
- 선택한 자막 설정은 영상 생성 요청과 결과물에 일관되게 반영되어야 한다.
- 자막의 모양은 사용자가 세부 설정하지 않아도 선택한 영상 스타일에 맞게 시스템이 자동으로 변경해야 한다.
- 현재 읽는 단어 또는 문장의 색상을 실시간으로 강조하는 효과는 첫 출시의 공통 자막 기능으로 제공하지 않는다.
- 읽기 강조 효과는 향후 해당 효과에 맞는 영상 형식 또는 스타일이 만들어질 때 그 스타일의 기능으로 적용한다.

### FR-011 ElevenLabs 목소리 선택

- 사용자는 영상 생성 전에 ElevenLabs를 통해 제공되는 나레이션 목소리를 선택할 수 있어야 한다.
- 선택 화면에는 사용자가 서로 다른 목소리를 구분할 수 있는 이름 또는 설명이 표시되어야 한다.
- 사용자는 목소리를 선택하기 전에 각 목소리의 짧은 샘플을 들어볼 수 있어야 한다.
- 선택한 목소리 정보는 영상 생성 요청에 포함되어야 한다.
- 완성 영상의 나레이션 전체에 사용자가 선택한 목소리가 일관되게 적용되어야 한다.
- ElevenLabs 연동 또는 선택한 목소리를 사용할 수 없는 경우 영상 생성 전에 사용자가 문제를 알 수 있어야 한다.

### FR-012 영상 비율 선택

- 첫 출시에서 사용자는 영상 생성 전에 `16:9`와 `9:16` 중 원하는 화면 비율을 선택할 수 있어야 한다.
- 선택 화면에는 각 비율의 형태와 용도를 사용자가 구분할 수 있게 표시해야 한다.
- 선택한 화면 비율은 영상 생성 요청에 포함되어야 한다.
- 이미지, 레이아웃, 자막, 전환과 모션 요소가 선택한 화면 비율에 맞게 배치되어야 한다.
- 완성 영상의 실제 해상도와 화면 비율이 사용자가 선택한 값과 일치해야 한다.
- 화면 비율이 달라져도 핵심 피사체나 텍스트가 잘리거나 화면 밖으로 벗어나지 않아야 한다.
- 기본값은 아직 확정하지 않았으며 현재는 `9:16`을 선호하는 잠정안만 있다.

### FR-013 자동 장면 및 샷 구성

- 슬라이드 이미지의 개수와 이미지가 전환되는 간격을 고정값으로 제한하지 않는다.
- 분석 Harness가 입력된 대본과 전체 영상의 흐름을 분석해 장면 구분, 이미지 수, 각 이미지의 유지 시간과 샷 전환 시점을 자동으로 결정해야 한다.
- 영상의 내용과 흐름이 달라지면 장면 구성과 샷 전환 타이밍도 그에 맞게 달라질 수 있어야 한다.
- 사용자는 이미지 수나 샷 전환 간격을 직접 설정하지 않는다.
- 자동으로 결정된 장면과 샷 구성이 나레이션 및 자막의 흐름과 자연스럽게 맞아야 한다.

### FR-014 비정형 대본 자동 해석

- 시스템은 나레이션 중심의 대본뿐 아니라 제목, 소제목, 번호, 장 구분, 메모와 괄호 속 연출 지시 등이 섞인 입력도 처리할 수 있어야 한다.
- 시스템이 실제로 읽을 나레이션과 읽지 않을 구조·메모·연출 지시를 자동으로 구분해야 한다.
- 읽지 않는 정보도 장면 구성에 도움이 되는 경우 영상 분석에 활용할 수 있어야 한다.
- 사용자가 별도의 형식으로 대본을 다시 작성하도록 요구하지 않아야 한다.
- 자동으로 정리된 나레이션을 영상 생성 전에 별도로 보여주거나 사용자 승인을 받는 단계는 현재 범위에 포함하지 않는다.

### FR-015 로그인 및 비로그인 체험

- 카카오, 네이버와 구글 소셜 로그인을 제공해야 한다.
- 비로그인 사용자도 대본을 입력하고 예상 영상 길이를 확인하는 등 실제 생성 직전까지 서비스를 체험할 수 있어야 한다.
- 실제 영상 생성은 로그인한 사용자만 시작할 수 있어야 한다.
- 비로그인 사용자가 `영상 만들기`를 누르면 로그인이 필요하다는 사실과 지원하는 로그인 방법을 안내해야 한다.
- 로그인 완료 후에는 생성 전에 입력·선택한 내용을 이어서 사용할 수 있어야 한다.

### FR-016 계정별 작업 목록 및 영상 보관

- 계정별로 완성 영상과 이전 영상 제작 작업의 목록을 제공해야 한다.
- 진행 중인 작업도 계정별 작업 목록에 표시하고 현재 진행 상태를 확인할 수 있어야 한다.
- 작업 목록의 각 항목에는 제목, 생성일, 대표 이미지, 영상 길이와 진행 상태를 표시해야 한다.
- 사용자는 나중에 다시 접속하고 로그인해 보관 중인 완성 영상을 재생할 수 있어야 한다.
- 사용자는 보관 중인 완성 영상을 다시 내려받을 수 있어야 한다.
- 초기에는 완성 영상을 별도의 만료 기한 없이 계속 보관한다.
- 장기적으로는 정해진 보관 기간이 지난 영상을 삭제하는 정책을 도입한다.
- 장기 보관 정책의 정확한 기간이 확정되기 전에는 임의의 기간을 적용해 영상을 자동 삭제하지 않는다.

### FR-017 나레이션 속도

- 사용자는 영상 생성 전에 나레이션 속도를 조절할 수 있어야 한다.
- 선택한 속도는 ElevenLabs 나레이션과 예상 영상 길이 계산에 모두 반영되어야 한다.
- 완성 영상 전체에서 선택한 나레이션 속도가 일관되게 적용되어야 한다.

### FR-018 배경음악

- 사용자는 대본 입력 화면에서 자신의 음원 파일을 함께 업로드해 배경음악으로 지정할 수 있어야 한다.
- 사용자에게 별도의 복잡한 음악 설정 화면이나 세부 음량 조절 기능을 요구하지 않는다.
- 사용자가 배경음악을 제공하면 시스템은 해당 음악을 결과 영상의 배경음악으로 사용해야 한다.
- 사용자가 음악을 제공하지 않으면 시스템이 영상 내용과 분위기 변화를 분석해 적합한 여러 배경음악을 자동으로 선택하고 필요한 구간에 배치해야 한다.
- 시스템은 나레이션이 잘 들리도록 배경음악의 음량과 나레이션과의 균형을 자동으로 조절해야 한다.
- 사용자가 배경음악 음량을 직접 설정하지 않아도 대본 전달을 방해하지 않는 수준으로 자동 믹싱되어야 한다.

### FR-019 완료 화면

- 영상 생성이 완료되면 완료 화면에서 결과 영상을 재생할 수 있어야 한다.
- 완료 화면에서 결과 영상을 내려받을 수 있어야 한다.
- 완료 화면에 `다시 만들기` 기능을 제공해야 한다.
- 사용자가 `다시 만들기`를 선택하면 입력 화면으로 돌아가지 않고 즉시 새로운 영상 생성 작업을 요청해야 한다.
- 새 작업은 기존 영상의 대본, 스타일, 목소리, 나레이션 속도, 화면 비율, 자막과 음악을 모두 그대로 사용해야 한다.
- `다시 만들기` 과정에서는 기존 입력과 설정을 변경하는 화면을 제공하지 않는다.
- `다시 만들기`는 결과 영상의 부분 편집이나 기존 파일 교체가 아니라 별도의 새 영상 생성 작업이다.
- 새 영상이 완성되어도 이전 영상은 삭제하거나 교체하지 않고 작업 목록에 함께 보관해야 한다.

### FR-020 자동 카메라 움직임·전환·강조 화면

- 슬라이드 이미지에 확대, 축소와 좌우 이동을 포함한 다양한 카메라 움직임을 사용할 수 있어야 한다.
- 디졸브를 포함한 여러 화면 전환 효과를 장면에 맞게 활용해야 한다.
- 사용할 카메라 움직임과 화면 전환 효과의 종류 및 적용 타이밍은 시스템이 대본과 장면을 분석해 자동으로 결정해야 한다.
- 시스템은 일반 자막 외에 제목 화면, 장 구분 화면과 중요 문장 강조 화면의 필요 여부 및 배치 시점을 대본과 장면에 맞게 자동으로 결정해야 한다.
- 사용자가 카메라 움직임, 전환 효과 또는 강조 화면을 직접 설정하지 않아도 영상이 완성되어야 한다.
- 자동 인트로, 자동 아웃트로, 서비스 로고와 워터마크는 결과 영상에 넣지 않는다.

### FR-021 자동 품질검사 및 작업 복구

- 생성 이미지가 대본의 내용과 크게 다르거나 인물, 글자 또는 구도가 명백하게 이상하면 사용자에게 공개하기 전에 해당 이미지를 자동으로 재생성해야 한다.
- 이미지, 나레이션, 자막, 렌더링 등 생성 과정에서 문제가 발생하면 감시자(supervisor)가 문제 원인을 수정하고 해당 작업을 복구하도록 시도해야 한다.
- 감시자의 수정 및 복구 시도가 실패한 경우에만 작업을 최종 실패로 처리해야 한다.
- 재시도 횟수와 복구 절차의 세부 구현은 별도로 정한다.
- 완료 처리 전에 최소한 검은 화면, 깨진 이미지, 음성 누락, 자막 불일치와 재생 오류를 자동으로 검사해야 한다.
- 필수 자동 검사를 통과하지 못한 결과물을 완료 영상으로 사용자에게 공개해서는 안 된다.

### FR-022 백그라운드 작업 및 완료 알림

- 사용자가 생성 진행 화면을 닫거나 서비스의 다른 페이지로 이동해도 서버의 영상 제작 작업은 중단되지 않아야 한다.
- 사용자는 나중에 작업 목록으로 돌아와 진행 중, 완료 또는 실패 상태를 다시 확인할 수 있어야 한다.
- 영상 제작이 완료되면 서비스 내부에서 완료 알림을 표시해야 한다.
- 이메일, 문자와 외부 메신저를 통한 완료 알림은 현재 제공하지 않는다.

### FR-023 다중 작업 큐 및 상태 관리

- 한 영상이 생성 중이어도 사용자는 다른 영상 생성을 추가로 요청할 수 있어야 한다.
- 각 생성 요청은 서로 구분되는 별도 작업으로 등록되어야 한다.
- 여러 작업은 큐와 상태 관리 체계에서 독립적으로 추적되어야 한다.
- 사용자는 작업 목록에서 각 작업의 진행 상태를 구분해 확인할 수 있어야 한다.
- 한 작업의 완료 또는 실패가 다른 작업이나 이전 완성 영상을 삭제하거나 교체해서는 안 된다.

## 5. 첫 출시 완성 정의

아래 조건은 첫 출시의 통과 기준이다. 아직 수치가 정해지지 않은 시험 기준은 `미확정 사항`을 결정한 뒤 보완한다.

### 5.1 핵심 사용성

- 영상 제작 경험이 없는 40~50대 핵심 사용자가 별도 교육 없이 `대본 입력 → 설정 선택 → 영상 만들기 → 결과 확인·다운로드` 흐름을 완료할 수 있다.
- 영상 제작 전문 용어나 편집 기술을 알아야만 진행할 수 있는 단계가 없다.
- 사용자가 직접 다루는 설정은 스타일, 목소리, 나레이션 속도, 화면 비율, 자막 포함 여부와 선택적인 사용자 제공 음악으로 제한되며 부분 편집 도구는 노출하지 않는다.
- 생성 중에는 일시정지·취소·부분 수정 기능이 노출되지 않는다.
- 비로그인 사용자도 대본을 입력하고 예상 영상 길이를 확인할 수 있으며, 실제 생성 요청 시점에만 로그인을 요구한다.
- 카카오, 네이버와 구글 계정 중 하나로 로그인할 수 있다.
- 모든 공개 스타일 선택 항목에서 해당 스타일의 대표 이미지를 확인할 수 있다.
- 모든 선택 가능한 ElevenLabs 목소리의 짧은 미리듣기를 재생할 수 있다.

### 5.2 대본 처리와 길이 제한

- 약 10분 분량의 나레이션 대본을 한 번에 붙여넣어 정상 처리할 수 있다.
- 제목, 번호, 메모 또는 연출 지시가 섞여 있어도 실제로 읽을 나레이션을 자동으로 구분한다.
- 정리된 나레이션을 별도로 확인받지 않고 다음 단계로 진행한다.
- 유효한 대본에는 별도의 최소 영상 길이를 적용하지 않는다.
- 예상 길이가 초기 최대치인 30분을 초과하면 생성 전에 차단하고 사용자가 이유를 알 수 있다.
- 최대 길이 안의 긴 대본도 여러 편으로 나뉘지 않고 하나의 완성 영상 파일로 출력된다.

### 5.3 슬라이드형 영상 결과물

- 선택한 스타일의 화면 구성과 시각적 특징이 결과 영상에서 확인된다.
- 서로 다른 공개 스타일로 만든 결과를 사용자가 시각적으로 구분할 수 있다.
- 분석 Harness가 대본의 의미와 흐름에 따라 장면 수, 이미지 유지 시간과 전환 시점을 자동으로 결정한다.
- 장면에 맞게 확대·축소·좌우 이동 등의 카메라 움직임과 디졸브 등의 화면 전환이 자동 적용된다.
- 카메라 움직임과 전환 효과의 종류 및 타이밍을 사용자가 지정하지 않아도 시스템이 자동 결정한다.
- 제목, 장 구분 또는 중요 문장 강조가 필요한 경우 시스템이 적절한 화면과 시점을 자동 결정한다.
- 슬라이드 이미지, 나레이션과 자막(포함을 선택한 경우)의 내용과 타이밍이 자연스럽게 연결된다.
- 적어도 같은 씬 안에서는 화풍, 인물, 장소와 주요 시각 요소의 일관성이 유지된다.
- 선택한 ElevenLabs 목소리가 영상 전체에 일관되게 적용된다.
- 선택한 나레이션 속도가 영상 전체와 예상 영상 길이 계산에 반영된다.
- `16:9`와 `9:16` 중 선택한 화면 비율과 실제 결과물의 비율이 일치하며, 핵심 이미지와 텍스트가 잘리지 않는다.
- 생성 화면에 처음 진입했을 때 자막 설정이 기본적으로 켜져 있다.
- 자막 포함을 선택한 영상에서는 자막 모양이 선택한 영상 스타일에 맞게 자동 적용된다.
- 자막이 읽기 쉬운 짧은 문장 단위로 나뉘고 각 문장이 나레이션 타이밍에 동기화된다.
- 첫 출시의 일반 자막에 현재 읽는 단어·문장의 색상 강조 효과가 공통으로 적용되지 않는다.
- 자막 미포함을 선택한 영상에는 자막이 나타나지 않는다.
- 사용자가 대본 입력 화면에서 음악 파일을 업로드한 영상에는 해당 음악이 배경음악으로 적용된다.
- 사용자가 음악을 제공하지 않은 영상에는 내용과 분위기 변화에 맞춰 시스템이 고른 여러 배경음악이 자동으로 배치된다.
- 별도의 복잡한 음악 설정이나 사용자 음량 설정 없이도 나레이션이 잘 들리도록 배경음악 음량과 균형이 자동 조절된다.
- 결과 영상에 자동 인트로·아웃트로, 서비스 로고 또는 워터마크가 포함되지 않는다.
- 대본과 크게 다른 이미지나 인물·글자·구도가 명백히 이상한 이미지는 사용자에게 공개되기 전에 자동 재생성된다.
- 검은 화면, 깨진 이미지, 음성 누락, 자막 불일치와 재생 오류 검사를 통과한 결과물만 완료 영상으로 제공된다.
- 완성 영상을 별도의 후편집 없이 내려받아 YouTube에 게시할 수 있다.

### 5.4 생성 진행과 결과 전달

- `영상 만들기`를 누르면 제작 현황을 중심으로 한 큰 진행 화면이 표시된다.
- 사용자는 새로고침하지 않아도 현재 작업 단계와 전체 진행률을 함께 확인할 수 있다.
- 사용자가 진행 화면을 닫거나 다른 페이지로 이동해도 서버 작업이 계속된다.
- 이미지·나레이션·자막·렌더링 문제는 감시자가 수정 및 작업 복구를 시도하고, 복구하지 못했을 때만 최종 실패 상태가 된다.
- 접수된 작업은 품질검사와 필요한 복구를 거쳐 정상 완료 또는 최종 실패 상태에 도달하고, 완료 시 같은 흐름에서 영상을 확인하고 내려받을 수 있다.
- 완료 화면에서 영상을 재생하고 내려받거나 `다시 만들기`를 선택할 수 있다.
- `다시 만들기`를 선택하면 입력 화면이나 설정 변경 단계 없이 같은 대본과 모든 기존 설정으로 별도의 새 생성 작업이 즉시 등록된다.
- `다시 만들기`로 새 영상이 완성되어도 이전 영상과 새 영상이 모두 작업 목록에 남는다.
- 한 작업이 생성 중인 상태에서도 다른 영상 생성 요청을 추가할 수 있고 각 작업의 상태를 독립적으로 확인할 수 있다.
- 로그인한 계정의 작업 목록에서 각 항목의 제목, 생성일, 대표 이미지, 영상 길이와 진행 상태를 확인할 수 있다.
- 영상이 완료되면 서비스 내부에 완료 알림이 표시된다.
- 이메일·문자·외부 메신저 완료 알림은 제공되지 않는다.
- 보관 중인 완성 영상은 나중에 다시 접속해 재생하고 재다운로드할 수 있다.
- 정확한 장기 보관 기간이 정해지기 전까지 완성 영상이 임의로 자동 삭제되지 않는다.

### 5.5 사용량

- 사용량과 잔액이 별도 크레딧이 아닌 `영상 제작 가능 시간`으로 표시된다.
- 30분, 1시간 등 정해진 시간 상품을 일시불로 구매할 수 있고 구독 결제가 발생하지 않는다.
- 구매한 영상 제작 가능 시간은 유효기간 없이 유지된다.
- 생성 전에 예상 영상 길이, 예상 차감 시간과 현재 제작 가능 시간을 확인할 수 있다.
- 예상 차감량보다 보유 사용량이 적으면 생성을 시작할 수 없다.
- 정상 완료된 영상은 실제 완성 길이를 기준으로 차감한다.
- 실제 영상이 예상보다 길어 현재 잔액을 초과하면 남아 있는 시간만 차감하고 잔액이 정확히 0이 된다.
- 차감 전후 어떤 시점에도 잔액이 음수가 되지 않는다.
- 사용자가 완성 영상을 받지 못한 실패 작업은 사용량이 차감되지 않는다.

### 5.6 출시 범위 판정

- 슬라이드형 영상은 위 조건과 별도로 정할 안정성 시험 기준을 충족해야 한다.
- 모션그래픽 영상은 첫 출시의 필수 완성 조건이 아니며, 준비되지 않은 상태로 공개하지 않는다.

## 6. 미확정 사항

- 핵심 사용자가 별도 도움 없이 영상을 완성했다고 판단할 사용성 검증 기준
- 첫 제작 완료까지 허용할 최대 단계 수와 목표 소요 시간
- 사용자가 부담할 수 있는 가격의 구체적인 기준
- 약 10분 영상의 목표 생성 소요 시간
- 최대 30분 영상의 제작 안정성을 충족했다고 판단할 시험 조건과 성공률
- YouTube에 바로 게시할 수 있다고 판단할 영상·음성 인코딩 규격과 품질 기준
- 대표 이미지 외에 스타일별 짧은 영상 예시를 추가로 제공할지 여부
- 스타일 대표 이미지의 크기, 비율과 갱신·검수 기준
- 스타일 선택의 기본값을 둘지 여부
- 한 영상 안에서 여러 스타일을 혼합할 수 있게 할지 여부
- 스타일별 품질을 어떤 기준과 절차로 검수할지
- 잠정 엔진·하위 스타일 분류와 명칭을 언제 어떤 기준으로 확정할지
- 현재 계획된 `귀여운 캐릭터 주도형`, `일본 판타지 애니메이션풍` 외에 첫 출시에서 추가로 제공할 스타일
- 서로 다른 씬에 반복 등장하는 동일 인물·장소의 외형을 어느 범위까지 일관되게 유지할지
- 같은 씬 안의 시각적 일관성을 충족했다고 판단할 구체적인 검수 기준
- 대본과 크게 다른 이미지, 이상한 인물·글자·구도를 판정하는 자동 검사 기준과 재생성 횟수
- 감시자가 자동으로 수정할 수 있는 문제의 범위, 복구 절차, 재시도 횟수와 최종 실패 판정 기준
- 검은 화면, 깨진 이미지, 음성 누락, 자막 불일치와 재생 오류를 검사하는 방법 및 통과 기준
- 전체 진행률의 계산 기준과 백분율 표시 방식
- 예상 남은 시간을 제공할지 여부와 계산 기준
- 영상 제작 가능 시간을 초 단위, 분 단위 또는 `시간:분:초` 중 어떤 형식과 정밀도로 표시·차감할지
- 빈 대본, 나레이션으로 해석할 문장이 없는 대본 또는 자동 구분이 불확실한 대본의 오류 처리 및 안내 방식
- 30분, 1시간 외에 판매할 시간 상품의 구성, 각 상품의 가격과 결제 수단
- 미사용 영상 제작 가능 시간의 환불 가능 여부, 환불 기간과 부분 환불 계산 방식
- 여러 작업을 큐에 넣는 순서, 우선순위와 실제로 동시에 처리할 수 있는 작업 수
- 여러 작업이 대기·진행 중일 때 각 작업의 잔액 검사, 사용 가능 시간 예약과 차감 순서
