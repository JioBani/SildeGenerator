# 새 대본의 표현 선택 시험

최종 상태: **GOAL_NOT_MET**. 비공개 `hybrid-story@0.9.1` 개발 후보이다.
공개 Astra·슬라이드 엔진·서비스·로그인을 바꾸지 않았고, 새 영상은 이번 시험에서 렌더하지 않았다.
기존0.9 소스는 `output/hybrid-story-0.9-baseline`에 보존했다.

## 시험 목적과 경계

새 대본에서 기존 영상을 돌려쓰는 대신 의미에 맞는 제작 경로와 시각화 문법을
실제 감독이 선택하는지 조사했다. 모의 응답이 아니라 서비스 전용 구독 브리지를
통한 `gpt-6-sol / low` 분석을 실행했다. 이미지·음성 제공자는 호출하지 않았다.

실행 전에 10개 짧은 대본과 예상 기준을 고정했다.
`experiments/meaning-planning-v1/routing-transfer-v1.json`의 기대값·사례 ID·판정 근거는
감독에게 보내지 않았다. 감독 입력은 각 대본과 기존 제작 능력 계약뿐이다.
결과를 본 뒤 기준을 수정해 통과율을 높이지 않았다.

이것은 제한적인 첫 노출 탐색 시험이다. 대표성 있는 보류 대본 벤치마크나
완성 영상 우세 시험이 아니다. 수정에 사용한 사례와 두 번째 실행은 개발 자료다.

첫 실행은 12회/161.177초, 재시험은 10회/160.906초였다. 이 한 쌍의 관찰만으로
속도나 첫 시도 성공률이 일반적으로 개선됐다고 결론 내리지 않는다.

원래 기대 문법과의 단순 일치는 8/10과 9/10이었다. **이 값은 정확도나 품질 점수가 아니다.**
배송 대본이 ‘순서만’ 설명하도록 쓰여 있어 단계 표현도 적합할 수 있었다.
반대로 이름이 맞아도 빈 설명 장면을 분리한 결과는 실행 가능한 계획이 아니다.
합격률을 꾸미지 않도록 원본 결과와 잘못 설정된 기대 기준을 그대로 보존했다.

## 구현한 수정

1. SDK에 선택적 `capability_reporting: required-grammar-0.1` 계약을 추가했다.
   기존 계약은 변경하지 않았다. 새 후보만 사용한다.
2. 감독이 필요한 문법을 먼저 명명하고 Core가 지원 여부를 따로 검사한다.
   스키마에 존재하지만 렌더러에 없는 문법은 이름을 보존해 구체적인 부족 기능으로 보고한다.
   null 문법, 엉뚱한 지원 문법, 이미지나 줌으로 우회하지 않는다.
3. 기존의 자산 생성 전 차단은 유지한다. 이번 수정은 지도 렌더러 구현이 아니다.
4. 독립 평가 도구에 두 시점 값을 누적량으로 바꾼 대조군과, 실제 감독 출력 두 개의 비교를 추가했다.
   실제 대안 비교에는 예상 승자나 ‘한쪽이 틀렸다’는 전제를 주지 않는다.
5. 평가 결과에 항목별 일치율과 불일치 위치를 추가했다. 승자가 같더라도 세부 판정이 다르면
   기존의 자동 승인 차단을 유지한다. 기준을 낮추지 않았다.

## 독립 평가 결과

생성 감독과 다른 `gpt-5.6-terra / low`가 A/B와 B/A 순서로 각각 평가했다.

- 저수조: 전후 비교와 잘못된 누적 비교를 구분했다. 8/8 판정 일치, 올바른 원본을 양방향 선택.
- 배송: 한 장면의 단계 표현을 양방향 선택했고, 빈 도입 및 경유 이동 능력 문제를 지적했다.
  하지만 세부 기준은 9/12만 일치했다. `ORDER_DISAGREEMENT`, 자동 승인 불가.
- 장난감: 하나의 인과 설명을 양방향 선택했다. ‘가상의 장난감 원리입니다’만 독립된
  인과 장면으로 만든 결함을 두 번 모두 탐지했다. 20/20 판정 일치.

이 평가는 대본·계획 평가이다. 실제 프레임, 연기, 디자인, 관객 이해도는 평가하지 않았다.
개별 비교의 100% 일치를 전체 평가기의 신뢰도나 보류 세트 성적으로 확대하지 않는다.
특히 평가기가 제안한 수정도 그대로 실행 명령으로 쓰지 않는다. ‘중립 도입 처리’ 같은
제안이 실제 지원 기능인지는 별도 계약 검사 대상이다.

## 증거와 사용량

- 종합 증거: `output/routing-transfer-audit-20260926.json`
- 첫 실행: `output/routing-transfer-first-01`
- 개발 재시험: `output/routing-transfer-regression-02`
- 독립 비교: `output/routing-snapshot-critic-01`, `output/routing-parcel-alternatives-01`,
  `output/routing-toy-alternatives-01`
- 각 입력·계약·엔진·응답·원문·평가 파일 해시를 연결했다.
- 실제 구독 호출 총28회: 분석22회, 독립 평가6회. 별도 유료 API0회, 이미지0회, 음성0회.
- 로그인 변경, 외부 API fallback, 운영 배포 없음.
- 기본 환경 검사 및 Harness 검증 통과.
- 변경 관련 회귀140개 통과(61.754초). 평가 진단 추가 후 관련15개 재검사 통과.
  두 수치를 서로 독립적인 테스트 개수로 합산하지 않는다.

## 다음 구현의 우선순위

1. 개별 장면에 해당 문법의 대상·관계·상태가 충분히 있는지 독립적으로 검사한다.
   면책·가정·도입을 따로 떼어 객체 없는 도식으로 만드는 사례를 실패 자료로 추가한다.
2. 이 의미 검사를 연구 명령뿐 아니라 실제 감독 경로의 장면 설계 전에 연결한다.
   자동 수정은 원문 순서를 보존하고 반복 상한을 공유해야 한다. 키워드로 강제 병합하지 않는다.
3. 단일 문법 이름이 아닌 보존할 정보와 필요한 실행 능력을 평가 기준으로 둔다.
   적합한 복수 표현을 허용하되, 경유점·인과·수량을 없애는 대체는 거부한다.
4. 통과한 자동 계획을 실제 영상으로 만들어 수치·동작·음성·글자 검사를 잇는다.
5. 지도·공간, 전체·세부, 분해·재결합, 증거·판단 등 미구현 표현을 실제 렌더 능력으로 추가한다.

목표는 미지원 입력을 잘 거부하는 것에 그치지 않는다. 다양한 정보를 실제로 표현하고,
새 대본에서도 같은 품질을 내는 것이 전체 목표다. 이번 결과는 그 연결의 결함과
평가 기준의 오류를 발견하고 한 가지 계약 모순을 고친 개발 증거이다.
