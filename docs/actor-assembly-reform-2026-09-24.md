# 인물 접합부 품질: 원인과 제작 공정 개편

작성: 2026-09-24. 대상: 빛 공해 실험 C. 서비스 자동 제작 경로는 변경하지 않는다.

## 결론

문제는 AI 그림 자체가 아니라, **독립 생성한 부품을 위치만 맞춘 것을 완성 리그로 취급한 조립 방식**이다.
이번 목은 빈 공간은 막았으나 기존 피부의 명암·광원·윤곽을 이어 그리지 않았다.
좋은 분리 마스크, 불투명한 덧댐, 영상 인코딩 성공은 각각 필요할 수 있지만 접합 품질을 보장하지 않는다.
이 보고서의 해결 방식은 제안이며, 새로운 저작 도구가 이 배우에서 성공했다고 주장하지 않는다.

## 코드에서 확인한 실패

- `build_light_pollution_story_ab.py`: 몸통과 머리를 별도 크기·위치로 맞춘다. 같은 원본 좌표에서 유도한 정합 증거가 없다.
- `build_light_pollution_reaction_v3.py`: 명암이 있는 피부 아래에 `#b17a55` 단색 다각형을 추가했다.
- 머리는 회전하지만 목의 보강층과 몸통은 고정이다. 빛 레이어도 머리에만 붙어 피부 경계의 광원 차이를 키울 수 있다.
- 기존 `verify()`는 영상 규격·프레임 수·음성 동일성을 확인했지만 목의 재질 연속성을 측정하지 않았다.
- `motion_assets.py`는 개별 자산의 anchor/pivot/review를 검사한다. 자산 사이의 접합부·공통 좌표·변형 영역은 별도 계약이 필요하다.
- 지금 이미지의 삼각형 경계는 단순한 투명도 문제가 아니다. 블러나 유사 색 채우기로 숨기는 것을 최종 해결로 삼지 않는다.

## 바꿀 제작 순서

1. **행동 범위부터 결정한다.** 눈 반응만 필요한지, 고개 회전·몸통 이동까지 필요한지 정한다.
2. **통 이미지로 디자인을 정하되 움직이지 않는 부분은 유지한다.** 얼굴 반응만 필요한 경우 목까지 굳이 절단하지 않는다. 다만 이 제한을 고개 연기 구현으로 포장하지 않는다.
3. **같은 마스터 문서에서 분리한다.** AI 개별 생성은 소재 초안이며 곧바로 조립 가능한 레이어가 아니다. 같은 캔버스에 등록한 뒤 비례·색·광원을 맞춘다.
4. **접합부마다 방식을 선택한다.** 의상 아래 숨길 접합, 연속 피부로 유지할 접합, 제한 메시로 구부릴 접합을 구분한다.
5. **가려질 영역을 미리 그린다.** 최대 이동·회전에서 드러날 영역에 안티앨리어싱 여유까지 포함한다. 무조건 몇 픽셀이라는 보편값을 두지 않는다.
6. **선의 주인을 정한다.** 턱·목·옷깃 경계를 어느 레이어가 그리는지 명시해 이중 선을 막는다.
7. **피부 명암과 조명을 분리한다.** 가능하면 동일한 피부 표면을 유지하고 움직이는 광원은 배우 그룹에 일관되게 적용한다. baked light가 있으면 중복 조명을 검토한다.
8. **정지 상태 재조립을 먼저 통과한다.** 원본과 재조립본을 동일 좌표에서 겹쳐 실루엣·경계·비례를 확인한다. 색·알파 오차와 사람 판정을 별도로 남긴다.
9. **정상 범위와 극단 자세를 모두 시험한다.** 눈만, 고개만, 몸통만, 결합 움직임을 분리해 문제 원인을 찾는다.
10. **실제 렌더 전 구간을 검사한다.** 접합부 확대, 흰색·검은색·체커 배경, 정속·느린 재생을 확인한다. 포즈 끝점만 보지 않는다.
11. **영상 규격 통과와 디자인 통과를 분리한다.** 기술 통과 + 자산 차단 상태를 동시에 표현한다.
12. **다른 대본으로 전이 후 승격한다.** 배우/리그/장면 프로그램 해시가 달라지면 기존 검수는 재사용하지 않는다.

## 이번에 구현한 범위

- 실험 전용 `scripts/actor_assembly_gate.py`: 접합 목록, 연속 명암면의 단색 보강, 정합 근거, 겹침 정책, 움직임 연결 누락 검사.
- 실제 비디오·프로그램·자산의 SHA-256 일치 확인. 파일이 바뀌면 기존 주석·판정을 무효화한다.
- 지정한 피부 두 영역의 색 차이를 전체 프레임에서 측정하고 최악 프레임·발생 횟수를 저장한다.
- 프레임 누락·화면 밖 측정 영역·빈 측정·지원되지 않는 계약을 통과시키지 않는다.
- 실험 C의 `verify()`에 연결. 영상 규격 PASS만으로 자산이 통과한 것처럼 표시하지 않는다.
- 깨끗한 측정도 `HUMAN_REVIEW_REQUIRED`까지만 허용한다. 자동 제작 승인은 하지 않는다.

아직 없는 것: ORA importer, 자동 마스크 겹침 검사, 랜드마크 정합 계산, 실제 메시 제작,
전체 캐릭터 경계 자동 검출, 접촉 추적. 현재 registration 근거는 파일 해시 연결까지만 검사하며,
등록된 랜드마크의 해부학적 정확도를 자동 판정하지 않는다.

## 실제 C 검사

282/282프레임을 해독했다. 목 위·아래 두 개의 7×7픽셀 영역을 측정했다.
색 차이 CIE76 중앙값 약 6.30, 최대 약 7.13, 최대 위치 106프레임이다.
시험 기준 5를 넘는 프레임은 282개다. **5는 Gold 기준이 아니라 이번 사례의 재검토 신호**다.
조명이나 의도된 명암도 색 차이를 만들 수 있으므로 이 값만으로 오류를 확정하지 않는다.
현재는 실제 사용자 지적, 코드의 단색 덧댐, 목 확대 영상이 함께 문제를 뒷받침한다.

이 프로브는 이 장면의 작은 움직임 범위에 한정된다. 카메라나 자세가 바뀌면 재주석 또는
좌표 추적이 필요하다. 전 프레임을 읽었다고 모든 피부·손·옷 경계를 검증한 것은 아니다.

## 다음 실제 저작 과제

대상은 동일 인물 1명, 동일 9.4초 장면이다. 먼저 한 문서에서 목을 옷깃 아래까지 이어 그리고,
원본과 같은 명암을 복원한 뒤 레이어와 좌표를 저장한다. 소프트웨어를 바꾸는 것만으로 통과시키지 않는다.

| 산출물 | 통과 기준 |
|---|---|
| master.kra + actor.ora | 승인 디자인과 같은 비례·피부·광원; 좌표·레이어 순서 보존 |
| registration.json | source hash, 공통 캔버스, 원본/레이어 대응점, 변환, 정합 오차 |
| join contract | neck-skin, collar-front, hair-back, cheek-hand별 소유권·가림·겹침 |
| rest reconstruction | 중립 조립 확대에서 틈·삼각 패치·이중 윤곽이 없음 |
| motion sweep | 허용 고개 각도 전 구간에서 목 늘어남·손 이탈·옷깃 침범 없음 |
| authored render | 기존 음성·길이 유지, 실제 프레임과 평가 파일 해시 연결 |
| human comparison | 접합 품질, 알아차림, 감정, 설명력을 따로 평가 |

OpenToonz와 Inochi2D는 동일 원본·같은 작은 고개 동작·동일 프레임으로 비교한다.
연속 피부 없이 단순히 기존 패치를 메시로 휘게 만드는 실험은 제외한다.
후보가 실패하면 이전 승인본을 보존하고, 최대 두 번의 원인별 수정 후 자산 저작으로 되돌린다.
