# 전후 수치 비교 문법 개발 기록

최종 상태: **GOAL_NOT_MET**. 새 기능은 비공개 `hybrid-story@0.9.0`에만 연결했다.
공개 `astra-motion`의 버전·서비스·인증을 바꾸지 않았다. 직전0.8 소스는
`output/hybrid-story-0.8-baseline`에 보존했다.

## 목표와 실제 범위

서로 다른 주제를 같은 이전 영상으로 대체하지 않고, 정보 관계에 맞는 문법을
선택하고 실행할 수 있도록 여섯 번째 문법 `before_after`를 추가했다.
현재 범위는 **같은 대상·측정 항목·단위의 두 시점 수치**이다.
증가·감소·변화 없음을 표현한다. 형태 변화·인물 변신·임의 시계열은 지원하지 않는다.
시간 순서를 원인으로 취급하지 않으며, 두 측정 사이의 값을 만들어내지 않는다.

`snapshot-pair-0.1`은 대상·항목·시간·값이 포함된 원문 인용 두 개를 요구한다.
Core는 인용·원문 순서·척도·단위·색상·버전을 확인한다. 이는 동일한 이름이
현실에서 실제로 같은 대상을 뜻한다는 독립 의미 검증을 대신하지 않는다.
렌더러는 동일한 영점과 척도를 쓰고 이전 값을 유지한 채 이후 값을 공개한다.
수치는 렌더러가 별도로 표시하며 제목·측정 항목·시점과 구획을 나눈다.

## 본체와의 연결

- 공개 SDK의 `hybrid-scene-0.5`, 전용 SnapshotPair 모델과 검증.
- 의미 분석에서 문법 선택 가능. 수치 두 개를 분리해 잃지 않도록 검사.
- 감독의 잠금형 장면 슬롯에는 수치 쌍만 제시하고, 불필요한 노드·화살표는 제외.
- 감독 결과의 버전·공유 디자인·원문을 기존 ScenePlan 경로로 전달.
- 콘셉트 평가기는 실제로 지원하는 두 시점 도형과 한계를 전달받음.
- 기존0.1~0.4 장면 재생과 이전 감독 계약 유지.
- 로컬 음성 단어 시점, 실제 출력 수치 검사, 정지 화면 검사에 새 문법 연결.

새 감독 경로는 MockTransport로 실제 Core 함수를 실행해 검증했다.
이번 세 영상은 사람이 작성한 개발 입력이므로 **미사용 대본의 자동 선택 성공**이나
구독 감독의 실제 신규 호출 성공으로 세지 않는다.

## 실제 출력

최종 비교 페이지: `output/snapshot-pairs-dev-04/review.html`.

| 개발 대본 | 수치 | 길이 | 실제 검사 프레임 | 막대 높이(검사 해상도) |
| --- | --- | --- | --- | --- |
| 같은 배터리 충전량 | 80% → 35% | 20.709초 | 496 | 96 → 42px |
| 같은 창구 대기 인원 | 12명 → 28명 | 19.000초 | 455 | 36 → 84px |
| 같은 창고 재고 | 45개 → 45개 | 18.750초 | 450 | 90 → 90px |

모두 가상 수치임을 음성과 자막에 명시했다. 1280×720,24fps,H.264/AAC.
원문·음성·계약·영상 해시는 receipt에 연결했다. 실제 자료 화면이 필요한 대본으로
위장하지 않았으며, 이미지나 자료를 재사용한 영상이 아닌 편집 가능한 도형 출력이다.

## 발견·수정·검수

1. 첫 출력은 수치 검사를 통과했지만 하단 설명이 자막에 가려졌다.
   `snapshot-pairs-dev-01`을 실패 디자인 증거로 보존했다.
2. 설명 위치와 값의 배치를 분리했다. 이후 중복 설명을 제거하고 자막 공간을 확보했다.
3. 허용 최대 길이 한글·긴 단위·시점으로 브라우저 글자 상자를 검사하자
   항목/값과 영점/시점 간 겹침이 드러났다. 감으로 반복하지 않고 실제 폰트 경계로
   배치 간격을 수정했다. 최대 길이 시험의 실패본·수정본도 각각 보존했다.
4. 최종 세 영상은 수치·타이밍·글자 위치 검사를 통과했다. 실제 최종 프레임도 보았다.

- 전체 회귀 140개 통과(63.683초). 마지막 배치 수정 후 관련14개 재검사 통과.
- 총1401프레임의 수치 높이·공개 시점·이전 값 유지 검사 통과.
- 시작 정지·완성 화면 고정·역재생은 세 영상 각각 거부(9/9).
- 최종 세 프로젝트의 브라우저 글자 경계 검사 통과.
- 아래로 내린 글자·왼쪽 밖 글자 대조군 탐지, 실제 첫 실패 디자인도 거부.
- 최대 허용 텍스트·글꼴 크기의 정적 스트레스 시험 통과. 이것은 영상/음성 검증이 아니다.
- Harness 검증과 Docker 기본 확인 통과. 실행 중인 서비스는 재시작하지 않았다.

수치 검사는 640×360으로 축소한 매 프레임을 검사하며 OCR은 아니다.
글자 경계 검사는 최종 정지 상태의 DOM과 자막 예약 영역을 검사한다.
전체 자막 글자·모든 시간대 미술·관객 이해도·독립 양방향 영상 평가는 아직 미완료다.
0 값에는 막대 면적이 없으므로 해당 숫자 텍스트의 실제 가시성은 별도 검수가 필요하다.

## 반복과 사용량

총4개 배치 후보(초안+3회 수정),각각3개 장면을 렌더했다.
음성은 최초3개 로컬 SAPI 발화만 생성하고 모든 수정에 같은 파일을 사용했다.
구독 감독 호출0회, 이미지 생성0회, 별도 유료 API0회, ElevenLabs0회.
최종 출력은 기술 개발 증거이며 자동 품질 승인이나 사람 승인으로 승격하지 않는다.

## 남은 전체 목표

전후 비교의 비수치 상태 표현은 아직 없다. 전체→세부, 분해·재결합,
증거→판단, 지도·공간 관계도 구현과 실제 출력 검증이 남아 있다.
새 정보 문법마다 원문·도형·시간표·출력 검사를 함께 추가해야 한다.
또한 독립적인 완성 영상 평가, 고정 보류 대본, 기본판 대비 우세,
자료 경로와 영화 장면의 통합 품질을 검증해야 한다.
세 개발 대본의 성공을 범용 전이 성공이나 TED-Ed 수준으로 확대하지 않는다.
